# Yandex Disk Sync для Obsidian

Плагин для ручной синхронизации хранилища Obsidian с папкой приложения на Яндекс Диске. В первую очередь рассчитан на Android, но также проверялся в работе под Windows 10.

Плагин работает через публичный API Obsidian и REST‑API Яндекс Диска. Node.js и Electron нужны только для сборки проекта, но не требуются на телефоне. Плагин не задействует Android AccountManager и не получает авторизацию из приложений Яндекса автоматически.

## Возможности

* умная двусторонняя синхронизация;
* отдельные команды «Загрузить» и «Скачать»;
* синхронизация только тех файлов, которые были изменены;
* использование SHA‑256 для сравнения содержимого файлов;
* пропуск файлов с одинаковыми хешами;
* определение случаев переименования и перемещения файлов по хешу;
* синхронизация переименований через операцию move — без повторной загрузки содержимого;
* по умолчанию применяется стратегия разрешения конфликтов «более новая версия считается актуальной»;
* альтернативные стратегии: всегда использовать локальную версию или всегда использовать удалённую версию;
* запрос подтверждения перед удалением файлов;
* перемещение удалённых файлов в корзину Яндекс Диска, а локальных — в корзину Obsidian;
* отображение прогресса, возможность отмены операции между файлами, повторное открытие окна с прогрессом;
* настройка исключений для отдельных файлов и папок;
* ограничение на максимальный размер файлов для устройств на Android.

## Важно перед началом работы

Плагин взаимодействует только с **папкой приложения**, а не со всем пространством Яндекс Диска. Для этого OAuth‑приложению необходимо предоставить право:

```text
cloud_api:disk.app_folder
```

Пример пути для синхронизации:

```text
app:/ObsidianVault
```

Не используйте в настройках обычный путь `/ObsidianVault` — он соответствует другому набору OAuth‑прав.

Вводить `Client secret` в плагин не нужно. Это серверный секрет, который небезопасно хранить в Android‑плагине. В текущем мобильном сценарии авторизации по OAuth используются Client ID и выданный access‑токен.

## Установка готовой сборки на Android

### 1. Соберите плагин

На компьютере в папке проекта выполните команды:

```cmd
npm install
npm run build
```

После сборки будут готовы следующие файлы:

```text
main.js
manifest.json
styles.css
```

### 2. Создайте папку для плагина в хранилище (vault)

Внутри нужного хранилища Obsidian создайте каталог:

```text
.obsidian/plugins/yandex-disk-sync/
```

Скопируйте в него файлы:

```text
main.js
manifest.json
styles.css
```

На Android это можно сделать с помощью файлового менеджера, через Obsidian Sync, Git или любым другим способом передачи файлов в vault.

### 3. Включите плагин

В Obsidian откройте:

```text
Настройки → Сторонние плагины → Yandex.Disk Sync → Включить
```

Если плагин не отображается в списке, проверьте правильность названия папки и наличие файла `manifest.json`.

## Первичная настройка авторизации через Яндекс OAuth

### Шаг 1. Зарегистрируйте приложение

В настройках плагина нажмите кнопку **«Открыть регистрацию»** либо откройте страницу вручную:

<https://oauth.yandex.ru/client/new>

В карточке приложения:

1. задайте название, например: `Obsidian Yandex.Disk Sync`;
2. в разделе доступа к данным выберите пункт:
   ```text
   Доступ к папке приложения на Диске
   ```
   Это право API имеет идентификатор:
   ```text
   cloud_api:disk.app_folder
   ```
3. сохраните настройки приложения;
4. скопируйте значение **Client ID**.

Значение `Client secret` сохраните только у себя — не вставляйте его в плагин.

### Шаг 2. Введите Client ID

В настройках Obsidian вставьте Client ID в поле:

```text
Шаг 2. Client ID OAuth-приложения
```

### Шаг 3. Получите токен доступа

Нажмите кнопку **«Открыть Яндекс OAuth»**.

В браузере на Android:

1. при необходимости войдите в нужный аккаунт Яндекса;
2. подтвердите предоставление доступа приложению;
3. скопируйте значение `access_token` со страницы результата.

Вы можете вставить в плагин либо только значение токена, либо полный URL страницы — плагин автоматически извлечёт из него `access_token`.

Токен выглядит примерно так:

```text
y0__xxxxxxxxxxxxxxxxxxxxxxxx
```

Не передавайте токен другим людям и не публикуйте файл с настройками плагина.

### Шаг 4. Укажите папку

В поле **«Папка на Яндекс Диске»** укажите отдельную подпапку внутри папки приложения, например:

```text
app:/ObsidianVault
```

Выбирать корневой путь `app:/` не следует.

### Шаг 5. Проверьте подключение

Нажмите кнопку **«Проверить»**. Успешная проверка означает, что Client ID, токен и право `cloud_api:disk.app_folder` настроены корректно.

## Использование плагина

В палитре команд Obsidian доступны три основные операции:

### Синхронизировать vault с Яндекс Диском

Рекомендуемый режим. Плагин сравнивает локальные и удалённые изменения и передаёт только необходимые файлы.

### Загрузить vault на Яндекс Диск

Односторонняя синхронизация в направлении:

```text
vault → Яндекс Диск
```

Удалённые файлы при этом не удаляются. Файлы, которые не изменились, пропускаются.

### Скачать Яндекс Диск в vault

Односторонняя синхронизация в направлении:

```text
Яндекс Диск → vault
```

Локальные файлы могут быть перезаписаны, поэтому перед началом операции плагин запрашивает подтверждение. Удаление локальных файлов не выполняется.

В левой панели Obsidian также доступны отдельные значки для запуска синхронизации, загрузки, скачивания и просмотра текущего прогресса.

## Как работает умная синхронизация

Плагин сравнивает три состояния файлов:

1. текущие файлы в хранилище (vault);
2. текущие файлы на Яндекс Диске;
3. состояние файлов после предыдущей синхронизации.

Метаданные хранятся в файле:

```text
.obsidian/plugins/yandex-disk-sync/sync-state.json
```

Для каждого файла сохраняются размер, дата изменения и хеш SHA‑256.

### Правила синхронизации

* Если хеш файла совпадает — файл не передаётся.
* Если изменился только локальный файл — он загружается на Яндекс Диск.
* Если изменился только удалённый файл — он скачивается в vault.
* Если изменились обе версии — применяется выбранная стратегия разрешения конфликта.
* Локальное переименование определяется как удаление файла по старому пути и появление нового файла с тем же хешем.
* Удалённое переименование обрабатывается аналогичным образом.
* Переименование выполняется через операцию move, содержимое файла повторно не передаётся.

### Разрешение конфликтов

По умолчанию используется стратегия:

```text
Более новая версия считается актуальной
```

То есть плагин сравнивает даты изменения файлов и не заменяет более новую версию старой.

В настройках доступны следующие варианты:

* **Более новая версия считается актуальной** — рекомендуемый вариант;
* **Всегда использовать локальную версию**;
* **Всегда использовать удалённую версию**.

### Обработка удалений

Перед удалением файлов плагин запрашивает отдельное подтверждение и показывает список файлов, которые предлагается удалить.

* Локальный файл перемещается в корзину Obsidian.
* Удалённый файл перемещается в корзину Яндекс Диска.
* Если вы откажетесь подтверждать удаление, файлы останутся на своих местах.

## Настройки для Android

### Исключения

По умолчанию исключены следующие папки:

```text
.obsidian/
.trash/
.git/
```

Дополнительные значения можно указать через запятую, например:

```text
.obsidian/, .trash/, Attachments/tmp/, *.tmp
```

### Максимальный размер файла

По умолчанию установлен лимит в 25 МБ. Он помогает снизить риск чрезмерного расхода памяти на устройствах Android. Файлы, размер которых превышает лимит, пропускаются при загрузке и скачивании.

### Сброс состояния синхронизации

Кнопка **«Сбросить состояние синхронизации»** удаляет только файл `sync-state.json`. Сами файлы в vault и на Яндекс Диске при этом не изменяются.

После сброса следующая умная синхронизация заново проанализирует файлы.

## Статистика и прогресс выполнения

После завершения операции плагин показывает:

* сколько файлов было загружено;
* сколько скачано;
* сколько переименовано;
* сколько удалено;
* сколько пропущено.

Если окно с прогрессом было закрыто или Android временно убрал его с экрана, нажмите значок **«Показать ход синхронизации»**.

## Типичные ошибки и их причины

### Ошибка 403

Проверьте следующее:

1. В настройках приложения выбрано именно право `cloud_api:disk.app_folder`.
2. Токен был получен после предоставления этого права.
3. В настройках плагина указан актуальный токен.
4. Путь к папке начинается с `app:/`, например `app:/ObsidianVault`.

После изменения прав в OAuth всегда получайте новый токен.

### Ошибка 401

Токен недействителен, истёк или был отозван. Получите новый токен через кнопку **«Открыть Яндекс OAuth»**.

### `Folder already exists`

Обычно это связано с временной задержкой индексации файлов в Obsidian на Android. В актуальной версии плагин проверяет наличие папки через файловый адаптер и должен продолжить операцию.

### Плагин сообщает, что синхронизация уже выполняется

Нажмите значок **«Показать ход синхронизации»** — он откроет текущее окно операции. Не запускайте вторую синхронизацию параллельно с уже идущей.

## Разработка проекта

Необходимые требования:

* Node.js версии 18 или выше;
* npm;
* типы API Obsidian из `node_modules`.

Установка зависимостей:

```bash
npm install
```

Проверка типов:

```bash
npm run check
```

Сборка для продакшена:

```bash
npm run build
```

Режим разработки с отслеживанием изменений:

```bash
npm run dev
```

Файл `main.js` — это результат сборки, он не хранится в Git согласно правилам `.gitignore`.

## Структура проекта

```text
src/
├── main.ts                 # команды и жизненный цикл плагина
├── syncEngine.ts           # логика выполнения синхронизации
├── yandexDiskClient.ts     # работа с REST‑API Яндекс Диска
├── hashUtils.ts            # вычисление SHA‑256 через Web Crypto
├── types.ts                # типы данных и настройки
├── sync/
│   ├── syncPlanner.ts      # трёхстороннее объединение (three‑way merge) и обработка переименований
│   └── syncState.ts        # работа с sync-state.json
└── ui/
    ├── settingsTab.ts      # интерфейс настроек плагина
    ├── confirmModal.ts     # модальные окна подтверждения действий
    └── syncProgressModal.ts# окно отображения прогресса операции
```

## Меры безопасности

* Не вводите `Client secret` в плагин.
* Не публикуйте OAuth‑токены.
* Не добавляйте файлы `data.json` и `sync-state.json` в репозиторий.
* Перед первой двусторонней синхронизацией сделайте резервную копию хранилища (vault).
* Для первой проверки используйте отдельную папку, например `app:/ObsidianVault`.
